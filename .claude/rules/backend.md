# Правила backend (`server/`)

Дополняют `ARCHITECTURE.md` (общая схема, «Кто за что отвечает», размер файлов, тесты рядом с файлом).
Загружаются только при работе с `server/`.

## Пакет и запуск

- Отдельный Node-пакет со своим `package.json`: Render собирает только каталог `server/`. Express 5,
  TypeScript запускается самим Node (type stripping), без сборки — поэтому только «стираемый» синтаксис
  (`erasableSyntaxOnly`) и импорты с расширением `.ts`.
- Импорты внутри пакета — через `#src/...` (поле `imports` в `server/package.json`), а не через `../`.
  Из `src/` клиента ничего не импортируем: пакеты собираются отдельно.

## Слои

```
server/src/
  index.ts          — точка входа: порт из PORT, запуск app
  app.ts            — сборка Express: CORS, роуты, обработчик ошибок
  routes/           — HTTP: читают и проверяют параметры, вызывают задачу, отдают JSON
  tasks/            — сценарии (findShowsPage, getAiringToday, getHiddenGems, addFavorite, getCached, …)
  storage/          — данные в памяти как база: get/set без правил (cache.ts, favorite.ts)
  api/              — клиент TVmaze (fetch) и типы
```

- **Роуты** не содержат бизнес-логики: параметры → задача → ответ. Неверные параметры — `400 { error }`,
  ошибка TVmaze — `502 { error }` (общий обработчик в `app.ts`).
- **Задачи** не знают об Express и HTTP: получают параметры и возвращают данные (или результат
  вида `{ ok: false, error }`, который роут переводит в статус).
- **Storage** — обычные объекты в памяти процесса с именованными операциями (`get`, `set`, `list`, `remove`).
  Правила (свежесть кэша, порядок, повторное добавление) — в задачах, а не в storage.
- **api/** — только `fetch` к TVmaze. Ошибка ответа — `TvmazeError` со `status`, чтобы задача отличала
  «шоу не найдено» (404) от сбоя TVmaze.

## Кэш

- Обычный объект `const cache = {}` в `storage/cache.ts`. Задача `getCached(key, load)`: если такой же запрос
  к TVmaze выполнялся меньше 5 минут назад, возвращает данные из кэша, иначе обращается к TVmaze и обновляет кэш.
- Неудачный запрос не кэшируется, устаревшие записи удаляются при записи новых.
- Ключ — смысл запроса (`search:<фраза в нижнем регистре>`, `index:<page>`, `schedule:<country>`, `show:<id>`),
  поэтому фильтр, сортировка и страницы одного поиска не вызывают новых запросов к TVmaze.

## Избранное

- Обычный объект `const favorite = {}` в `storage/favorite.ts` (ключ — id шоу), одно на весь сервер,
  живёт до перезапуска процесса.
- API: `GET /api/favorites` (новые первыми), `PUT /api/favorites/:id` (ответ — шоу), `DELETE /api/favorites/:id`
  (`204`). `PUT` и `DELETE` идемпотентны.
- Клиент присылает только id: данные шоу сервер берёт у TVmaze сам (через кэш), поэтому сохранить выдуманные
  данные нельзя. Неизвестное шоу — `404`, неверный id — `400`.

## Типы ответа

- `Show`, `SearchPage` описаны и в `server/src/api/types.ts`, и в `src/api/types.ts`: пакеты собираются
  отдельно. При изменении ответа меняем оба файла.

## Тесты

- Лежат рядом с файлами и запускаются тем же `npm test` (проект Vitest `server`, окружение `node`).
  API тестов (`describe`, `it`, `expect`, `vi`, …) глобальное, как на клиенте: из `vitest` не импортируем.
  Исключения из «у каждого файла свой тест»: `index.ts` и хелперы `test*.ts` (`testServer.ts`, `api/testShows.ts`).
- Роуты тестируем через `request()` из `testServer.ts` (настоящий HTTP на свободном порту) с замоканными задачами.
- Задачи — с замоканным `api/tvmaze.ts` (или замоканными задачами нижнего уровня) и очищенным storage
  (`cacheStorage.clear()`, `favoriteStorage.clear()`) в `beforeEach`.

## Деплой

- Render по `render.yaml`: каталог `server`, `npm ci`, `npm start`, health check `/api/health`.
- В production CORS разрешён только домену клиента (`CORS_ORIGIN`), локально — любой источник.
